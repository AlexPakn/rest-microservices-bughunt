# REST microservices bug hunt

Навчальне завдання з пошуку дефектів у трьох REST-сервісах: Auth, Product, Order.
Підготовлено вихідну версію, 13 окремих виправлень, pytest-тести, звіт і матеріали для PR.

## Перевірка без Docker

Рекомендований Python — **3.11**, як у Dockerfile; локально перевірено на Python **3.12.14**
з точними основними версіями залежностей із завдання. Python 3.13 для цього набору
старих залежностей не рекомендований: для pydantic-core може не бути готового wheel.

У PowerShell у корені проєкту:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe scripts/verify.py
.\.venv\Scripts\python.exe scripts/smoke_http.py --start
```

`verify.py` запускає однаковий набір тестів для початкових та виправлених сервісів,
не перемикаючи вашу гілку. Для нього потрібні Git та тег `baseline`.
`smoke_http.py --start` запускає три Uvicorn-процеси на портах 8001–8003,
перевіряє реальний HTTP і зупиняє створені процеси. Зайняті порти спричиняють відмову запуску.

У вже підготовленому робочому каталозі є ізольоване оточення **поруч із проєктом**:

```powershell
..\.venv-rest-bughunt\Scripts\python.exe -m pytest -q
..\.venv-rest-bughunt\Scripts\python.exe scripts/verify.py
..\.venv-rest-bughunt\Scripts\python.exe scripts/smoke_http.py --start
```

Це оточення прив'язане до цього комп'ютера і не переноситься разом із репозиторієм.

## Запуск у Docker

Після встановлення Docker Desktop із Docker Compose:

```powershell
docker compose up --build -d
python scripts/smoke_http.py
docker compose down
```

Для HTTP-перевірки Python має бути з оточення, де встановлені залежності.
Тести на Python 3.11 всередині контейнера:

```powershell
docker compose -f compose.test.yml run --build --rm tests
```

На комп'ютері підготовки Docker відсутній: складання образів і контейнерний запуск **не перевірені**.
Синтаксис Compose та команд запуску Dockerfile перевірено локально.

| Сервіс | Адреса | Інтерактивна документація |
|---|---|---|
| Auth | http://localhost:8001 | http://localhost:8001/docs |
| Product | http://localhost:8002 | http://localhost:8002/docs |
| Order | http://localhost:8003 | http://localhost:8003/docs |

Compose `depends_on` задає порядок запуску; він не гарантує готовності HTTP.
Сценарій smoke очікує готовності, а Order повертає явні помилки 502/504 при збоях залежностей.

## Межі навчального рішення

Дані та сесії зберігаються в пам'яті одного процесу, після перезапуску зникають.
Тестові паролі з умови залишено відкритими; для реальної системи потрібні хешування,
стійке сховище, HTTPS, обмеження спроб входу й централізована робота із сесіями.
Токени випадкові та мають TTL 1 годину; JWT не використовується.

Перевіряється поточний залишок товару, але **бронювання та списання запасів не реалізовані**.
Повторні чи паралельні замовлення можуть перевищити сумарний залишок. Для реальної торгівлі
потрібні атомарна операція резервування та узгоджене відновлення після збоїв.
Ціни — JSON-числа за обраним контрактом; грошові розрахунки тут не виконуються.
Для розрахунків слід узгодити Decimal або цілі мінімальні грошові одиниці.
