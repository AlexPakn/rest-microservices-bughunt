# Узгоджений REST-контракт

Тіло запиту та відповіді — JSON. Секрети передаються в тілі POST або заголовку
Authorization; не в URL. Паролі й токени не записуються застосунками в журнали.
У прикладах `<issued-token>` — позначення токена, отриманого після входу.

## Auth

`POST /login`

```json
{"email":"alice@example.com","password":"alice123"}
```

Успіх: `200`, поля `access_token` (випадковий рядок), `token_type: "bearer"`,
`expires_in: 3600`, `user_id: 1`. Неправильні дані входу: `401`;
відсутні/некоректні обов'язкові поля: `422`. GET для `/login`: `405`.

`GET /whoami` із `Authorization: Bearer <issued-token>`:

```json
{"email":"alice@example.com","user_id":1}
```

Успіх: `200`. Відсутній, невідомий, неправильно оформлений або прострочений токен: `401`
із `WWW-Authenticate: Bearer`. Назва схеми Bearer нечутлива до регістру.
Query-параметр `authorization` не використовується для авторизації.

## Product

`GET /products` → `200`, `{"items":[...]}`.

`GET /products/100` → `200`:

```json
{"product_id":100,"name":"Keyboard","price":59.99,"stock":5}
```

`product_id` — додатне ціле, `name` — непорожній рядок,
`price` — скінченне невід'ємне JSON-число, `stock` — невід'ємне ціле.
Відсутній товар: `404`, `{"detail":"Product not found"}`.
Неціле значення параметра шляху: `422`.
Однакова схема Product використовується у списку й детальній відповіді.

## Order

Усі `/orders` потребують Authorization.

`POST /orders`:

```json
{"productId":100,"qty":2}
```

Імена вхідних полів збережено з умови через Pydantic aliases.
Обидва значення — строго додатні цілі: рядки, bool, null, дробові числа,
невідомі поля та пропущені поля не приймаються (`422`).

Успіх: `201`:

```json
{"order_id":1,"user_id":1,"product_id":100,"quantity":2,"status":"created"}
```

Спочатку перевіряється особа через Auth, потім товар через Product.
Користувач визначається відповіддю Auth; клієнт не задає `user_id` замовлення.

| Умова | Статус |
|---|---:|
| Немає токена / Auth відмовив | 401 |
| Auth явно повернув заборону доступу | 403 |
| Товар не існує | 404 |
| `qty` більше за `stock` | 409 |
| Помилка вхідної схеми | 422 |
| Збій з'єднання, неочікуваний статус, JSON або схема залежності | 502 |
| Таймаут залежності | 504 |

При відмові замовлення не додається до пам'яті. Order використовує таймаут HTTPX 5 секунд
на мережеві операції та не переходить за redirect. Це не загальний дедлайн всього запиту.

`GET /orders` → `200`, `{"orders":[...]}` лише для поточного користувача;
без токена `401`. Для недоступного Auth діють ті самі правила 502/504.

## Межі контракту

`stock` перевіряється в момент запиту; бронювання та списання відсутні.
Idempotency key, транзакції, постійне зберігання, платіжні операції та API реєстрації не входять
у підготовлений стенд. Рядкове подання ціни само по собі припустиме для іншого контракту;
тут свідомо вибрано числове подання відповідно до підказки завдання.
